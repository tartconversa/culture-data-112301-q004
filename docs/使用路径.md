# 业务使用路径：从推广增量到可兑现承诺

本文档说明运营如何使用本应用把游戏取景地宣传带来的兴趣评估为新增到访，
再据此决定向旅行社承诺多少可兑现的预约量，并在履约后完成溯源。
所有结论仅来自 `data/` 中的合成资料；应用状态写入 `state/`，报告写入 `outputs/`。

```sh
python3 -m tourflow.cli validate                 # 1. 资料校验
python3 -m tourflow.cli analyze                  # 2. 增量测算
python3 -m tourflow.cli forecast                 # 3. 需求预测与回测
python3 -m tourflow.cli plan                     # 4. 承诺试算（不落账）
python3 -m tourflow.cli plan --commit            # 4'. 承诺试算并落账
python3 -m tourflow.cli accept --group G5        # 4''. 单个团体接受（幂等）
python3 -m tourflow.cli fulfill                  # 5. 履约：关闭/核销/接驳
python3 -m tourflow.cli audit                    # 6. 溯源与可承诺量变化
python3 -m tourflow.cli demo                     # 依次跑通 1–6
```

常用参数：`--now` 业务时点（影响报价失效判断）；`--conservatism` 保守程度；
`--control-scope strict|include_spillover` 对照范围；`--bootstrap` 自助法次数；
`--seed` 随机种子（默认固定，结果可复验）。

## 1. 资料校验 validate

按 `data/catalog.json` 校验内容指纹、行数、主键、字段类型与直接外键。
任何资料损坏都会在此步暴露，后续步骤不会在不一致资料上运行。

## 2. 增量测算 analyze → outputs/incrementality.{json,md}

估计每条推广线路的新增到访与不确定性：

- 分析单位为客源地×日×线路；到访次数是次数而非人数。
- 对每个已推广客源地，用“整个比较窗口内未启动任何推广、且未被资料确认的
  外溢联系波及”的客源地做干净对照，按 Callaway–Sant'Anna 风格的 2x2 比较
  估计事件时间系数，基期取推广前 14 天可用观测的均值。
- 分析者可指定比较范围（`--control-scope`）；选择包含外溢客源时报告会标注
  识别风险。对照不足的单元不估计，列入无法识别清单，不做外推。
- 实施前趋势按事件周分箱做联合检验；报告给出前置偏差量级及其占估计效应的
  比例，占比过半即降级为“证据不足”。
- 售罄日为右截尾观测，主口径剔除；敏感性口径保留并标注向下偏误方向。
- 唯一游客经抽样行程调查换算：linked 记录按匿名人去重，unlinked 记录只给
  区间；调查未覆盖的线路只给无信息区间。同一人跨场馆到访不会被加总为新增人数。
- 每条线路给出判定：支持归因 / 证据不足 / 无法识别。证据不足的增量只进入
  待验证，不能当成已证实成果。

## 3. 需求预测 forecast → outputs/forecast.{json,md}

按客源地×线路×日给出供承诺使用的需求范围：

- 每个客源地×线路拟合截尾泊松模型：趋势 + 推广后变化 + 假日 + 降雨；
  售罄日按右截尾处理（忽略截尾会系统性低估需求），关闭日不进入拟合。
- 输出自然需求（推广后置零）与推广变化的分解；预测区间含参数不确定与
  抽样噪声，分位数供承诺策略选用。
- 回测为时间外推：用截止日前数据拟合，评估其后 28 天的 MAE、偏差与
  80% 区间覆盖率，写入报告。
- 预测日期超出拟合窗口时逐行标注外推风险。

## 4. 承诺试算 plan / accept → outputs/plan.{json,md}

把预测折算为可承诺量并对团体请求逐一决策：

- 可承诺量 = 需求分布的某个分位（由 `--conservatism` 选择：越保守分位越低）。
  推广变化只有在增量测算支持归因时全额计入；证据不足时只按
  `--pilot-fraction` 计入小规模试行。应用不设置任何“热度指数直接占量”的通道。
- 资源约束：场馆日容量、保护区人流上限（另有 `--protected-util-cap` 缓冲）、
  共享接驳车次座位；已售散客与其他已确认团体先行扣减。
- 整团承诺全有或全无：线路全部场馆与接驳同时满足才成立；请求线路不可行时
  按约定的整条替代线路尝试，人数不自动缩减。
- 同一团体重复接受只产生一次承诺；待确认报价不重复占量，过期即释放。
- 已接受团体不被牺牲：新承诺只使用剩余容量。
- 报告列出每个团体的决定与绑定约束，以及拒绝需求、预计闲置与保护区压力；
  调整 `--conservatism` 重跑即可比较三者如何变化。试算（不加 `--commit`）
  与落账在同一本容量账上顺序扣减，两者结果一致。

## 5. 履约 fulfill → outputs/fulfill.{json,md}

应用 `later_events` 中的后续事实：

- 场馆临时关闭：为受影响承诺在约定替代线路中寻找仍满足已接受权益的整条
  替代，容量账同步改写；无约定替代则进入退款，有替代但不可行则转人工协商。
  承诺记录始终保留，不能简单删除。
- 核销与交通回执用于区分未到访、线路替代与服务取消；核销率回写为客源地的
  履约反馈，关闭单元进入推广观察期的排除清单，二者都影响下一轮决策。

## 6. 溯源 audit → outputs/audit.{json,md}

- 每次 analyze/forecast/plan 都登记为一次运行（配置、资料指纹、结果摘要），
  运行 id 由内容派生，可复验。
- 每项承诺记录其依据：分析运行 id、策略参数与容量指纹；历史承诺如实标注
  无分析依据。履约结果（核销人数、分类）挂在同一链条上。
- 第二轮预测之后，报告分解可承诺量变化：先容量（承诺占用与关闭）后需求
  （新到访资料引起的预测修订），让负责人能追查下一轮可承诺量为何改变。

## 可复验测试

```sh
python3 -m unittest discover -s tests -v
```

- `test_did.py`：已知真值的合成面板上找回效应、执行对照纪律、识别截尾与
  前置趋势背离。
- `test_survey.py`：跨馆去重、linked/unlinked 区间、完全可观测场次区分。
- `test_demand.py`：截尾泊松找回已知参数；忽略截尾显著低估。
- `test_capacity.py`：容量扣减、共享接驳不按线路相加、关闭阻断。
- `test_commit.py`：全有或全无、幂等接受、失效、替代、不驱逐既有承诺、
  试算与落账一致。
- `test_fulfill.py`：关闭替代保人数、退款/协商留痕、核销分类、事件幂等。
- `test_audit.py`：运行登记、溯源链条、可承诺量分解恒等式。
- `test_cli.py`：用仓库合成资料在临时目录跑通整条业务路径并校验不变量。
- `test_loader.py` / `test_materials.py`：资料校验与损坏检测。

## 合成资料读取说明

资料为 UTF-8 JSONL，每行一条记录；`data/catalog.json` 登记各表字段、类型、
主键、直接外键与内容指纹。代码读取方式：

```python
from tourflow.materials import load
materials = load(".")            # 校验指纹与模式后载入
rows = materials.table("daily_panel")
```

字段口径以 `docs/资料契约.md` 为准：日期为公历，带 Z 的时间为 UTC；
`null` 表示缺失，空列表表示已知集合为空；不同来源与业务时期的记录各自
保留身份，不能仅按文件行数解释业务数量。
